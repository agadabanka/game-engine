Studio IDE — Design Doc

An AI-first cockpit for one game. Stay in the AI-first world; drop down to the knobs only when you want fine-grain control over a small part of a larger blueprint.

Engine repo: agadabanka/game-engine · Epic: #53 · Tracks issues #54–#63 · 2026-06-15

1. Why this exists

Today the only thing a human can author by hand on a shipped game is a free-text note.

The pipeline (tools/lib/pipeline.mjs, 4 phases / 19 stages / 72 substeps) turns a one-line concept into a finished game, written almost entirely by AI agents. Around the result we have:

  • The hub (hub/public/index.html) — read-only “look across / look inside” every game.
  • Per-game views — build.html (level select), design.html (the lens), diary.html. All read-only.
  • The one write gesture — in-game ⏸ → 📝 NOTE (Studio.Shell.note → POST /api/notes), which auto-files a GitHub issue and captures level, x, kind, and a screenshot.

So the owner can describe a change (a note) and wait for the whole pipeline, or hand-edit raw files / run CLIs. There is no place to sit inside one game and turn a specific knob with the AI beside you. The Studio IDE is that place — the missing middle.

2. The vision & principles

Keep the workflow AI-first: play the game, leave notes to improve it. When you want fine-grain control, drop down into the IDE — still an AI-first world, but focused on a smaller part of a larger blueprint. Each part of the game (a level, the cast, the art, the music, the feel) is a tool that can be edited and put back, gated by the same validators the pipeline uses.

PrincipleWhat it means in the UI
The note is the universal verbAt every altitude, the primary gesture is leaving a note. A note is also the entry that drops you into the right tool.
AI-first, knobs-availableThe prompt bar is the primary input in every tool. The knobs are there for when you know exactly what you want — and they write the same structured fields the AI writes, so they never drift.
Nothing ships ungatedEvery put-back must pass the stage’s validator (0-death, parity, sprite-alternation, FUN). The blueprint never enters a state the gate didn’t certify.
Small PRs on a large blueprintEach put-back is scoped to one artifact, certified by one validator, recorded in the diary, and closes its originating note.
Reuse, don’t rebuildThe blueprint is hub/lib/stages.js; the preview is the existing scoped game + Studio.Autopilot; the gates are the existing CLIs.

6. The round-trip — “edit a part and put it back”

Every tool implements the same five steps. This is the contract the whole IDE is built around.

#StepMechanism
1Read the artifact, scoped to the selected elementgame /api/meta or the repo file (levels.js, characters.js…)
2Edit via AI prompt or knobs — both emit the same structured field-changeagent (NL → edit object) ↔ inspector (direct → edit object)
3Preview live, scoped, autopilot-playedembedded game at ?level=N&char=key + Studio.Autopilot
4Gate — the stage’s validator runs as a job; Put back stays disabled until greeneval.mjs / validate-sprites.mjs / parity.mjs / fun-max.mjs
5Put back — write file · commit to branch · append diary · close the notenew authed POST /api/<artifact> + GitHub MCP commit + DELETE /api/notes

7. The note → drop-down flow

This is the heart of the design: how you go from playing to fine-grain control without leaving the AI-first world.

  1. Play the live game (the AI-first world). A gap keeps killing you → ⏸ → 📝 note: “this gap before the goal feels unfair.” (Works today; captures level:3, x, screenshot.)
  2. The note lands on the blueprint, auto-routed by its metadata: level → Levels node, kind:art → Art node. The node lights up: “Levels ● 1 note.”
  3. The AI takes a first pass automatically — beyond filing the issue, it drafts a candidate diff in the routed tool. The board reads “Level 3 · 1 proposed fix.”
  4. If the AI’s pass is enough → Accept from the board. Never opened the IDE. Pure AI-first. ✓
  5. If you want control → “Open in IDE.” You drop into the Levels tool, scoped to Level 3, note pinned at its x, the AI’s diff pre-loaded, knobs live. A small part of the larger blueprint, still AI-first.
  6. Nudge the gap knob or re-prompt → preview the autopilot clear it → 0-death gate goes green → Put back. The note/issue closes; the diary gets an entry; the blueprint node goes green.

8. The /api surface

The IDE reads what already exists and adds a small set of authenticated write endpoints, mirroring the existing notes admin-token guard (x-admin-token === NOTES_GH_TOKEN).

Reads (exist today)

GET /api/meta     game identity + stages (drives the blueprint + Identity tool)
GET /api/diary    the build diary (markdown)
GET /api/notes    open/closed notes, each carrying level · x · kind · shot
GET /api/config   engine/renderer info

Writes (new, authenticated)

POST   /api/levels      x-admin-token  → validate + write src/game/levels.js
POST   /api/characters  x-admin-token  → validate + write src/game/characters.js
POST   /api/meta        x-admin-token  → merge + write GAME_META.json
DELETE /api/notes?id=   x-admin-token  → dismiss a handled note   (exists today)

Each write is schema-validated server-side, persists the artifact, and is followed by a branch commit (via GitHub MCP from the IDE host) + a diary append. Art/Music put-backs trigger their generators (tools/art*.mjs, tools/music.mjs) rather than a raw file write.

9. Architecture & data flow

  hub (/ide)  —reads→  game /api/{meta,notes,diary}     → Blueprint + Stage + Notes board
      │
   agent  —proposes→ structured edit object  ↔  Inspector knobs   (same object)
      │
   gate job —runs→  eval.mjs / parity.mjs / validate-sprites.mjs / fun-max.mjs
      │
   Put back —→ POST /api/<artifact> (authed) → write file
                 → GitHub MCP commit to claude/… branch
                 → DIARY.md append  → close note + issue
                 → refreshed blueprint node status

The edit object is the spine: the agent and the knobs both produce it, the diff renders it, the gate validates the artifact it would produce, and the put-back persists it. Keeping a single representation is what lets AI and direct manipulation coexist without drift.
